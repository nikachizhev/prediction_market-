# Рынок прогнозов

Внутренний рынок предсказаний на виртуальные монеты: команда прогнозирует события, участвует в опросах и сравнивает результаты. Стек: Python, Django 5, PostgreSQL 17, шаблоны Django и Chart.js.

## Возможности

- Регистрация на сайте и прямо в Telegram-боте; подтверждение почты обязательно для новых аккаунтов.
- Покупка и продажа бинарных акций через LMSR, LS-LMSR или CPMM.
- Анонимные опросы, числовые прогнозы и множественный выбор.
- Создание вопросов с критериями результата, дедлайном и динамическими вариантами ответов.
- История вероятности, поиск, фильтры и сортировка рынков.
- Личный рейтинг: участие, сделки, покупки, продажи, выплаты и точность.
- Проводники Веста, Клёп и Фокс с общим прогрессом; маленького проводника в углу можно скрыть.
- GitHub-источник, демонстрационная A/B-платформа и административная панель.

## Первый запуск в Windows

Нужны Python 3.12+ и запущенный Docker Desktop с Linux-контейнерами.

```powershell
git clone https://github.com/nikachizhev/prediction_market-.git
cd prediction_market-
git switch backend-market-pages
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
docker compose up -d --wait
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Если репозиторий уже есть, работайте в его папке. Существующий `.env` не перезаписывайте. Активация окружения PowerShell не требуется: команды вызывают Python напрямую.

Откройте [сайт](http://127.0.0.1:8000/) или [регистрацию](http://127.0.0.1:8000/register/). Для разработки шаблон использует отправку писем в терминал: найдите ссылку подтверждения в выводе сервера, откройте её и нажмите кнопку подтверждения. Реальная доставка настраивается ниже.

Для следующих запусков:

```powershell
docker compose up -d --wait
.\.venv\Scripts\python.exe manage.py runserver
```

Остановка сайта — `Ctrl+C`. Остановка базы — `docker compose stop`; данные сохраняются в томе `postgres_data`.

## Настройки и база

Локальные значения задаются в `.env`, образец — [.env.example](.env.example).

| Переменная | Назначение |
| --- | --- |
| `DJANGO_SECRET_KEY` | Секрет Django; смените перед развёртыванием |
| `DJANGO_DEBUG` | `1` для разработки, `0` для развёртывания |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Параметры PostgreSQL |
| `POSTGRES_HOST`, `POSTGRES_PORT` | По умолчанию `127.0.0.1:5432` |
| `SITE_URL` | Адрес сайта в письмах и Telegram-ссылках |
| `GITHUB_TOKEN` | Необязательный токен GitHub API |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | Токен и имя бота без `@` |
| `TELEGRAM_APP_NAME` | Short name Mini App из BotFather (`t.me/<бот>/<app>`), по умолчанию `app` |
| `MEDIA_ROOT` | Папка для фото-доказательств, по умолчанию `media/` |
| `METABASE_DB_PASSWORD`, `METABASE_PORT` | Пароль роли `metabase_ro` для дашборда и порт Metabase (по умолчанию `3000`) |

Приложение использует PostgreSQL. Модели описаны в `market/models.py`, изменения схемы — в `market/migrations/`. Миграции хранятся в Git; после обновления проекта выполняйте `manage.py migrate`.

Если открываете письма или Telegram на телефоне, `SITE_URL=http://127.0.0.1:8000` не подойдёт: укажите доступный этому устройству адрес. `runserver` — сервер разработки, для публикации нужен отдельный сервер приложения и настройка HTTPS.

## Mini App в Telegram

Mini App — это SPA из папки `miniapp/` (React + Vite + TypeScript). Django отдаёт собранное приложение по адресу `SITE_URL/app/`, API — по `/api/` (контракт — [docs/api.md](docs/api.md)). Нужен Node.js 18+.

**1. Сборка и данные.**

```powershell
cd miniapp
npm install
npm run build
cd ..
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_miniapp --reset
```

`seed_miniapp` создаёт 7 демо-рынков с недельной историей сделок. После изменений во фронтенде снова выполните `npm run build`.

**2. HTTPS-туннель.** Telegram открывает Mini App только по HTTPS. Для разработки подойдёт туннель к локальному серверу, например:

```powershell
ngrok http --url=<ваш-домен>.ngrok-free.dev 8000
```

Бесплатный аккаунт [ngrok](https://ngrok.com) даёт один постоянный домен (раздел Domains в кабинете), поэтому адрес в BotFather и `.env` задаётся один раз: `SITE_URL=https://<ваш-домен>.ngrok-free.dev`, затем перезапустите сервер. При первом открытии ngrok показывает страницу-предупреждение — нажмите «Visit Site». Без регистрации подойдёт `ssh -R 80:localhost:8000 nokey@localhost.run`, но его адрес регулярно меняется.

**3. BotFather.** Используйте отдельного тестового бота, не боевого. Команда `/newapp` → ваш бот → название, описание, картинка 640×360 → Web App URL `https://<адрес>/app/` → short name `app` (как `TELEGRAM_APP_NAME`). При смене адреса: `/myapps` → бот → Edit Web App URL.

**4. Запуск** — каждая команда в своём терминале:

```powershell
.\.venv\Scripts\python.exe manage.py runserver
.\.venv\Scripts\python.exe manage.py setup_bot
.\.venv\Scripts\python.exe manage.py run_telegram_bot
.\.venv\Scripts\python.exe manage.py run_worker
```

`setup_bot` достаточно выполнить один раз после смены `SITE_URL`. `run_worker` раз в минуту закрывает приём прогнозов, спрашивает создателей об итоге, шлёт напоминания, отменяет рынки без итога через 72 часа, завершает окно спора и рассылает выплаты.

Откройте бота, нажмите `/start` → «Открыть приложение» или откройте ссылку `t.me/<бот>/app`.

**Бот: «Мои рынки» и «Поделиться».** Команда `/my` (или кнопка «Мои рынки» в `/start`) показывает отслеживаемые рынки; по нажатию на рынок бот присылает анимацию графика за неделю. Для анимации нужен `ffmpeg` в `PATH` (в Windows — `winget install ffmpeg`, в Ubuntu — `sudo apt install ffmpeg`); без него бот отвечает текстом. Чтобы работало «Поделиться» (карточка рынка из Mini App и `@бот <запрос>` в любом чате), включите инлайн-режим: в @BotFather `/setinline` → ваш бот → подсказка, например «Найти рынок». Картинка-график в карточке появляется, только если `SITE_URL` начинается с `https://`.

**Разработка без Telegram.** Сервер принимает только подписанные Telegram данные, поэтому для браузера подпишите тестовые данные токеном из `.env` и запустите Vite (он проксирует `/api` на `127.0.0.1:8000`):

```powershell
.\.venv\Scripts\python.exe manage.py make_init_data --first-name Тест
```

Выведенную строку положите в `miniapp/.env.local` как `VITE_DEV_INIT_DATA=...`, затем в папке `miniapp` выполните `npm run dev`. Строка действует 24 часа.

**Модерация.** Споры решаются в админке (`/admin/`): раздел «Вопросы», фильтр «Разрешение: Спор у модератора», действия «Решение по спору: ДА / НЕТ / отменить рынок». Рынок, скрытый после трёх жалоб, возвращается действием «Вернуть скрытый жалобами рынок в ленту».

**Отдельный бот жалоб.** Команда `manage.py run_moderation_bot`, отдельные `MODERATION_BOT_TOKEN` и `MODERATION_ADMIN_IDS` в `.env`. Все жалобы доставляются разрешённым администраторам, решения доступны в личном чате и сохраняются в истории. Инструкция настройки, правила решений и запуск на сервере — [docs/moderation-bot.md](docs/moderation-bot.md). Создавать бота и запускать его нужно отдельно; существующий пользовательский токен не использовать.

## Деплой на сервер

Продакшен работает на VPS с Ubuntu 26.04. Caddy выпускает HTTPS-сертификат и проксирует запросы в gunicorn, Postgres запущен в Docker, бот и фоновый воркер — сервисы systemd. Все файлы лежат в `deploy/`, код сервер берёт из ветки `main` на GitHub.

Первая настройка (на сервере, под root). Вместо `<host>` подставьте имя сервера: подойдёт бесплатное `<ip-через-дефисы>.sslip.io`, например `91-108-241-25.sslip.io`.

```bash
apt-get update && apt-get install -y git
git clone -b main https://github.com/nikachizhev/prediction_market-.git /opt/prediction_market/app
bash /opt/prediction_market/app/deploy/setup-server.sh <host>
nano /opt/prediction_market/app/.env          # TELEGRAM_BOT_TOKEN и TELEGRAM_BOT_USERNAME
bash /opt/prediction_market/app/deploy/update.sh
sudo -u pm /opt/prediction_market/venv/bin/python /opt/prediction_market/app/manage.py setup_bot
```

`setup-server.sh` сам создаёт `.env` со случайными `DJANGO_SECRET_KEY` и паролем Postgres. В BotFather для Mini App указывается `https://<host>/app/`.

Обновление: запушьте изменения в `main`, затем выполните (из Windows — в PowerShell, там тоже есть `ssh`):

```bash
ssh root@<ip> bash /opt/prediction_market/app/deploy/update.sh
```

Логи: `journalctl -u pm-web -u pm-bot -u pm-worker -f`.

## Дашборд в Metabase

Дашборд для команды (спека, E7) — [Metabase](https://www.metabase.com) в Docker. Он читает только схему `analytics`: представления без имён, псевдонимов, username, Telegram ID и фото. Схему создаёт миграция (только в PostgreSQL), роль `metabase_ro` может читать её и больше ничего.

1. В `.env` задайте `METABASE_DB_PASSWORD` (любой длинный пароль) и при желании `METABASE_PORT`.
2. Запустите базу и Metabase, примените миграции и создайте роль:

```powershell
docker compose --profile metabase up -d
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py setup_metabase_role
```

   `setup_metabase_role` можно запускать повторно: он обновляет пароль и права. Запустите его снова после миграций, которые добавляют представления.
3. Откройте `http://127.0.0.1:3000` (или ваш `METABASE_PORT`), создайте администратора и добавьте базу: тип PostgreSQL, хост `db`, порт `5432`, имя базы — `POSTGRES_DB` из `.env`, пользователь `metabase_ro`, пароль — `METABASE_DB_PASSWORD`. В настройках подключения ограничьте схемы схемой `analytics`.

Без `--profile metabase` команда `docker compose up -d --wait` по-прежнему запускает только PostgreSQL. Данные Metabase (вопросы, дашборды) лежат в томе `metabase_data`.

| Дашборд | Представления `analytics` |
| --- | --- |
| Аудитория: DAU / WAU / MAU, удержание 1/7/30 дней | `active_users`, `retention` (когорты по дню регистрации), `activity`, `signups` |
| Воронка: открыл → первый прогноз → вернулся на следующий день → создал рынок, отдельно для пришедших по приглашению | `funnel` (колонка `referred`), `funnel_users` — для фильтра по дате регистрации |
| Экономика: монеты появились и сгорели за день, всего монет, доля балансов меньше 100 | `economy_daily` |
| Рынки: создано / разрешено / отменено / оспорено, часы от даты итога до разрешения | `markets_daily`, `market_resolution_delays` |
| Свои графики | `traders`, `markets`, `trades`, `ledger`, `events`, `disputes` |

Дни считаются по Москве. «Сгорело» — то, что ушло из оборота на завершённых в этот день рынках: половина комиссии, потерянная подписка создателя, проигранные споры.

На сервере Metabase не запускается сам (`pm-db` поднимает только базу). Чтобы включить, добавьте `METABASE_DB_PASSWORD` в `/opt/prediction_market/app/.env` и выполните `cd /opt/prediction_market/app && docker compose -p prediction_market --profile metabase up -d`, затем `sudo -u pm /opt/prediction_market/venv/bin/python manage.py setup_metabase_role`. Порт открыт только на `127.0.0.1`, поэтому заходите через SSH-туннель: `ssh -L 3000:127.0.0.1:3000 root@<ip>` и `http://127.0.0.1:3000`.

## Почта Mail.ru

В настройках Mail.ru разрешите доступ внешних приложений и создайте пароль приложения. В `.env` задайте:

```dotenv
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.mail.ru
EMAIL_PORT=465
EMAIL_USE_SSL=1
EMAIL_USE_TLS=0
EMAIL_HOST_USER=sender@example.com
EMAIL_HOST_PASSWORD=your-app-password
DEFAULT_FROM_EMAIL=sender@example.com
```

Адрес отправителя должен соответствовать используемому ящику. После изменения настроек перезапустите сайт и бота.

Ссылка подтверждения действует 24 часа и используется один раз. Повторное письмо можно запросить на `/email/pending/` или командой `/resend` в боте, не чаще раза в минуту. Новая отправленная ссылка заменяет предыдущую. Если SMTP недоступен, аккаунт остаётся неподтверждённым и не может войти; повторная регистрация не нужна.

При ошибке подключения проверьте сеть из обычного PowerShell:

```powershell
Test-NetConnection smtp.mail.ru -Port 465
```

Для локальной отладки:

```dotenv
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
```

В этом режиме письмо печатается в терминале, но не отправляется адресату. Секреты и пароли не добавляйте в репозиторий.

## Telegram

Создайте бота через [BotFather](https://t.me/BotFather), командой `/newbot`. Заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME` в `.env`. В отдельном терминале запустите один экземпляр:

```powershell
.\.venv\Scripts\python.exe manage.py run_telegram_bot
```

Используется long polling: публичный webhook не нужен. Если у бота уже установлен webhook, перед запуском его необходимо отключить.

Кнопку меню «Открыть приложение» (ведёт на `SITE_URL/app/`) и список команд бота настраивает один запуск после развёртывания или смены `SITE_URL`:

```powershell
.\.venv\Scripts\python.exe manage.py setup_bot
```

Итог рынка создатель указывает в боте: кнопки ДА / НЕТ / «Отменить рынок» в сообщении бота или ссылка «Указать итог» из приложения (`/start resolve_<id>`), затем фото или скриншот, предпросмотр и «Подтвердить». Участники рынка получают итог с фото и кнопкой «Оспорить» (спор стоит 20 монет). Фото сохраняется в `MEDIA_ROOT`.

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие и кнопка «Открыть приложение» (для привязанного аккаунта — меню) |
| `/register` | Регистрация: имя → почта → подтверждение письмом |
| `/cancel` | Отмена диалога регистрации |
| `/resend` | Повторная отправка письма |
| `/login` | Одноразовая ссылка для входа на сайт |
| `/balance` | Текущий баланс |
| `/menu` | Меню с кнопками |
| `/markets` | До 5 новых открытых вопросов с действующим дедлайном |
| `/positions` | Активные позиции, выплаты при выигрыше и собственные ответы |
| `/myquestions` | До 5 последних созданных вами вопросов |
| `/stats` | Участие, точность, прибыль, выплаты и место в рейтинге |
| `/unlink` | Отключение Telegram, если у аккаунта есть пароль |

После подтверждения почты отправьте `/login`, откройте кнопку и нажмите «Войти на сайт». Ссылка действует 10 минут; новая отзывает предыдущую. Не пересылайте её другим людям.

Можно начать регистрацию через кнопку Telegram на сайте. Этот запрос привязан к браузеру и также действует 10 минут. Если аккаунт уже существует, сначала войдите на сайт и подключите Telegram в разделе «Мои ставки»: совпадение почты само по себе не объединяет аккаунты. Там же доступны проверка связи и отключение.

### Бот в закрытом чате

У чата Telegram могут быть свои рынки, которые видят только его участники.

1. В @BotFather: `/setjoingroups` → ваш бот → `Enable`, чтобы бота можно было добавлять в группы. Режим приватности (`/setprivacy`) оставьте включённым: бот видит в чате только команды и служебные сообщения, переписку не читает.
2. Добавьте бота в чат **администратором**. Особые права не нужны; право закреплять сообщения — по желанию. Только админам Telegram сообщает, кто в чате и кто вышел, поэтому без админства бот объясняет это и пространство не создаёт.
3. Бот пишет приветствие с кнопкой «Открыть рынки чата» и, если может, закрепляет его. Если бота удалить или снять с админа, рынки чата замораживаются: новых нет, открытые доживают до итога. Вернули админом — всё оживает с той же ссылкой.

Команды в чате: `/markets` — открытые рынки, `/top` — рейтинг чата, `/settings` — настройки для админов (какие сообщения бот пишет в чат, ИИ-помощник, цена создания рынка). Новые рынки, итоги с фото и топ-3 недели бот пишет сам, не больше 5 сообщений в день и не ночью (23:00–09:00 МСК); за это отвечает `run_worker`.

После обновления, в котором поменялись команды бота, выполните ещё раз:

```powershell
.\.venv\Scripts\python.exe manage.py setup_bot
```

## Типы вопросов

| Тип | Участие и результат |
| --- | --- |
| LMSR | Акции ДА/НЕТ; чувствительность задаётся постоянным параметром `b` |
| LS-LMSR | Акции ДА/НЕТ; глубина растёт с открытыми акциями |
| CPMM | Акции ДА/НЕТ через пул с постоянным произведением резервов |
| Анонимный опрос | Один вариант на человека, без монет; правильного ответа нет |
| Угадай число | Одно число в диапазоне; точность проверяется с заданным допуском |
| Множественный выбор | Один или несколько вариантов; нужен точный набор правильных ответов |

В разделе «Рынки» нажмите «Создать рынок». Автор задаёт дедлайн и правило «Как определяем результат», затем публикует результат на странице вопроса. Участие автора запрещено. После дедлайна сервер не принимает новые сделки и ответы. Неторговой ответ отправляется один раз и не меняется.

Выигравшая акция выплачивает 1 монету, проигравшая — 0. При аннулировании возвращается оставшаяся учтённая стоимость позиции. В опросах, угадайке и множественном выборе монеты не списываются.

Анонимность опросов действует в интерфейсе: индивидуальные ответы и имена не публикуются. Связь ответа с аккаунтом хранится в базе для защиты от повторного голосования и не является криптографической анонимностью.

### Математика

- LMSR: `C(q) = b · log(sum(exp(qᵢ/b)))`.
- LS-LMSR: `b(q) = α · sum(qᵢ)`, `α = 0.05`. Используется положительная затравка `b_initial/(2α)` для каждой стороны. Цена вычисляется через полную производную стоимости; отображаемая вероятность нормализована и отличается от цены покупки.
- CPMM: `pool_yes · pool_no = constant`, начальные резервы равны выбранной ликвидности. Обычный торговый оборот сам по себе не увеличивает ликвидность.

Источники: [исследование LS-LMSR](https://www.cs.cmu.edu/~sandholm/liquidity-sensitive%20automated%20market%20maker.teac.pdf), [реализация CPMM в Manifold](https://github.com/manifoldmarkets/manifold/blob/main/common/src/calculate-cpmm.ts).

## Рейтинг и проводники

Рейтинг показывает активность за 30 дней, диаграмму точности и итог по последним завершённым торговым рынкам. Лидерборд сравнивает торговую прибыль, включая оценку открытых позиций. Каждый первый заход на страницы сайта за день даёт 5 монет и 2 XP; день определяется по Москве. Награда записывается отдельно, повторные посещения и вкладки не дают дополнительного начисления. Бонусные монеты исключены из прибыли, XP сохраняется при смене проводника. Посещения через API и Telegram не дают ежедневную награду.

«Мой рейтинг» показывает участие в вопросах, число операций, сумму покупок, доход от продаж, выплаты, прибыль, верные и неверные ответы.

Для завершённого торгового рынка прогноз определяется преобладающей оставшейся позицией ДА/НЕТ. Равные и полностью проданные позиции исключены из точности. Для числа учитывается допуск, для нескольких вариантов — точное совпадение. Опросы и аннулированные вопросы не входят в точность. Место определяется числом верных, затем меньшим числом ошибок и прибылью. Стоимость открытых позиций оценочная и не равна гарантированной сумме продажи.

После первого входа доступны Веста, Клёп и Фокс. Их можно менять, прогресс общий:

- 10 XP за участие в отдельном прогнозном вопросе;
- 20 XP за верный прогноз;
- бонус `floor(sqrt(сумма покупок))`, максимум 50 XP.

Повторные сделки не увеличивают число участий. Продажи не уменьшают накопленный объём покупок. Опросы и аннулированные вопросы исключаются из опыта.

| Уровень | Требования |
| --- | --- |
| Ученик | Начальный |
| Предсказатель | 100 XP и 2 верных |
| Звёздный проводник | 300 XP и 7 верных |
| Оракул | 700 XP и 15 верных |

Проводник отображается в углу страниц. Крестик скрывает его, кнопка ✧ возвращает; настройка сохраняется в профиле. Нажатие открывает прогресс. Уровни отличаются звёздами и свечением.

## Источники вопросов

GitHub-адаптер обнаруживает milestones с дедлайном и issues с меткой `predict` в этих milestones. При закрытии или наступлении срока определяет исход; `not planned` аннулирует вопрос. Исполнители исключаются из торговли. Повторные синхронизации не создают дубликаты.

`abmock` — локальная демонстрационная платформа экспериментов. Рынок создаётся по черновику, закрывается при запуске, разрешается по одностороннему z-тесту: `p < 0.05` → ДА, иначе НЕТ. Отмена эксперимента аннулирует рынок. Это ещё не интеграция с внешней A/B-платформой.

```powershell
.\.venv\Scripts\python.exe manage.py sync_sources
# Либо периодически:
.\.venv\Scripts\python.exe manage.py sync_sources --loop 60
```

## Профиль и друзья

Настройки профиля доступны через меню аккаунта: имя, псевдоним, необязательные дата рождения, город, работа, учёба и описание. Дополнительные поля видны только владельцу. Telegram подключается там же; выбор проводника остаётся отдельным пунктом меню. GitHub указывается вручную, без OAuth.

В разделе «Друзья» можно найти участника по логину, отправить и принять заявку, отменить её или удалить друга. На странице вопроса ссылка «Предложить друзьям» отправляет приглашение подтверждённому другу. Приватный вопрос можно предложить только другу, который уже состоит в соответствующей группе.

Восстановление пароля доступно по ссылке «Не помню пароль» на странице входа. Письмо отправляется на подтверждённую почту активного аккаунта с установленным паролем; ссылка действует один час и используется один раз. Telegram-аккаунт без пароля входит через бота.

## Группы и приватные рынки

В меню «Мои группы» можно создать сообщество или рабочую группу с названием и описанием. Создатель становится администратором. Он приглашает пользователей по логину, принимает и отклоняет заявки и удаляет участников. Приглашённый пользователь сам подтверждает вступление. Поиск по названию показывает описание группы; её рынки, репозитории и состав доступны только участникам.

При создании вопроса поле «Где опубликовать» предлагает общий рынок и ваши группы. Из группы можно перейти к форме с уже выбранной группой. Групповые рынки доступны её участникам на сайте, через API и в Telegram; прямые ссылки не открывают доступ посторонним. Выход или исключение прекращает доступ, при этом существующие позиции и финансовая история сохраняются, выплаты по завершению выполняются.

В рабочей группе администратор подключает GitHub-репозитории. Кнопка «Синхронизировать» импортирует вопросы только в эту группу. Фоновая команда `sync_sources --loop 60` синхронизирует все настроенные источники. Вопросы создаются по milestones с датой и issues с меткой `predict`, привязанным к таким milestones. Повторная синхронизация не создаёт дубликатов. Один репозиторий может использоваться разными группами с независимыми рынками.

По умолчанию групповой источник обращается к GitHub без серверного токена и читает публичные репозитории. Для закрытого репозитория администратор сайта проверяет права и включает «Доступ серверным токеном одобрен администратором» в разделе GitHubRepo; нужный доступ должен быть у `GITHUB_TOKEN`. Участники групп не получают сам токен. Общие источники и глобальная синхронизация управляются сотрудниками сайта через `is_staff`.

## Уведомления

Колокольчик в верхнем меню показывает число непрочитанных событий: заявки в друзья, принятые заявки, приглашения в вопросы и группы, заявки на вступление и результаты рынков с вашим участием. Список обновляется при открытии и каждые 30 секунд на активной вкладке. Кнопка «Открыть» помечает событие прочитанным и ведёт к вопросу, группе или друзьям. На отдельной странице доступны последние 100 событий и действие «Прочитать все». События записываются в той же транзакции, что и изменение состояния рынка.

## Панель рисков и отчёт группы

На странице группы доступны «Панель рисков» и «Отчёт по результатам». Эти страницы видят только активные участники. В риски включаются GitHub-вопросы и ручные бинарные вопросы с дедлайном и отметкой «ДА означает выполнение в срок».

Панель выделяет вероятность ниже 50% при дедлайне в ближайшие 7 дней, падение от 15 процентных пунктов за неделю (или с создания), меньше трёх участников, отсутствие ставок три дня и ожидание результата. Это ориентиры для внимания, а не гарантия срыва или статистическая оценка достоверности.

Отчёт показывает итоги всех завершённых вопросов, участие, выполнение сроков и Brier для бинарных прогнозов. Для оценки берётся историческая вероятность за сутки до дедлайна; если исход зафиксирован раньше — за сутки до фиксации. Вопросы без ставки к этому моменту и старые исходы без сохранённой даты исключаются из оценки. Дата фиксации результата сохраняется для новых завершений; прежним результатам дата не придумывается.

## Подписки

На странице вопроса «Следить без ставки» включает уведомления о результате. Для торгового рынка также приходят изменения вероятности от 10 процентных пунктов относительно последнего уведомления, не чаще одного раза в час. Подписки собраны в верхнем меню. Монеты не списываются. После выхода из группы её вопросы и уведомления перестают отображаться; новые события подписчику без доступа не отправляются.

## Проверка покупки

Покупка выполняется одним нажатием «Купить акции». Стоимость и возможная выплата видны рядом с суммой. Кнопка «?» открывает на той же странице информационное окно с количеством акций, выплатой, прибылью и максимальной потерей; открытие окна не списывает монеты. Окончательная цена рассчитывается сервером в момент покупки. Проверки доступа, баланса, лимитов и CSRF сохраняются.

Каждая форма покупки получает подписанный идентификатор, связанный с участником и вопросом. Повторная отправка той же покупки возвращает прежнюю сделку без второго списания; новая форма позволяет купить ещё, в том числе на ту же сумму. Идентификатор сохраняется в сделке атомарно с балансом. Формы, открытые до обновления, нужно перезагрузить.

Стоимость оставшихся акций учитывается отдельно для ДА и НЕТ. Продажа уменьшает только стоимость проданной стороны пропорционально числу акций; при отмене возвращается сумма обеих оставшихся стоимостей. Миграция `0014_purchase_safety` восстанавливает этот учёт по истории сделок, не меняя балансы и ранее выполненные выплаты. Перед её применением сделайте резервную копию БД и остановите процессы, создающие сделки.
