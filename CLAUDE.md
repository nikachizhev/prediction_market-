# CLAUDE.md — рынок прогнозов в Telegram

## Что делаем

Рынок прогнозов на виртуальные монеты внутри Telegram: **Mini App** (лента, ставка, создание рынка, статистика) и **бот** (отслеживаемые рынки, уведомления, разрешение рынка создателем с фото). Вход только через Telegram. Монеты нельзя купить или вывести.

Проект с 25.10.2026 поворачивает из «внутреннего рынка для компании» в Mini App. Старые части (почта, GitHub-источник, A/B-заглушка, маскоты, серверные шаблоны) ещё в коде — см. «Что есть сейчас».

## Стек и запуск

- Python 3.12, Django 5.2, PostgreSQL 17 в Docker, `requests`, `python-dotenv`. Тесты: `pytest` + `pytest-django`.
- Фронтенд Mini App: SPA (React + Vite + TypeScript) в папке `miniapp/`. Старое правило «никакого SPA» отменено.
- Окружение — в `.env` (образец `.env.example`). Порт PostgreSQL берётся из `POSTGRES_PORT`: на машине Кирилла это **5433**, потому что 5432 занят системным Postgres.

Команды (Linux; в Windows вместо `.venv/bin/python` — `.\.venv\Scripts\python.exe`):

```bash
docker compose up -d --wait                                  # PostgreSQL
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_demo --reset                 # демо-данные
.venv/bin/python manage.py runserver                         # http://127.0.0.1:8000
.venv/bin/python manage.py run_telegram_bot                  # бот, long polling, нужен TELEGRAM_BOT_TOKEN
.venv/bin/python -m pytest --ds=config.test_settings -q      # быстрые тесты на SQLite в памяти
.venv/bin/python -m pytest --ds=config.postgres_test_settings -q   # + проверки блокировок на настоящем PostgreSQL
```

`pytest.ini` по умолчанию берёт `config.settings` (нужен запущенный PostgreSQL). На 25.10.2026: 183 теста зелёные, 2 пропущены — им нужен PostgreSQL.

## Правила, которые нельзя нарушать

**Деньги**
- Любое изменение балансов и состояния рынка — только через `market/services.py`. Вьюхи, API, бот и фоновые задачи вызывают сервис, сами баланс не трогают.
- Каждая сделка, выплата и отмена — в `transaction.atomic()` с `select_for_update()` на рынок и участников.
- Суммы — `Decimal`, квантуем до 0,01. Математика LMSR — во `float`, результат в `Decimal`. Стоимость сделки округляем **вверх**, списание при продаже — вниз: на округлении нельзя «печатать» монеты.
- Покупки идемпотентны через `Trade.request_key` — повтор запроса не списывает второй раз.
- Параметры экономики из спеки (E5) живут в одном месте в `config/settings.py`, не в коде экранов: стартовый пакет 1000, бонус дня 20, лимит сделки 20% баланса и не больше 200, не больше 500 в один рынок, создание рынка 100 (b = 144), комиссия 2% (половина создателю, половина сгорает), спор 20. Сейчас в настройках старые значения (`LMSR_DEFAULT_B = 200`, `MAX_BET = 300`) — их меняет задача по экономике.
- Бонусные монеты не входят в прибыль для рейтинга.

**Доступ и приватность**
- Видимость рынков — только через `visible_questions(trader)` из `market/access.py`. Чужой приватный рынок возвращает 404.
- Кто как поставил, видит только сам участник; остальным — цена, график, анонимная лента, объём, число участников.
- Создатель рынка не может делать прогнозы на свой рынок.

**Telegram**
- Пользователь определяется только по проверенной подписи `initData` (HMAC с ключом бота) или по апдейту бота. Telegram ID из тела запроса без подписи не принимается.
- Секреты (токен бота, ключи) — только из окружения. `.env` не коммитить.

**Код**
- Идентификаторы и комментарии — по-английски, весь текст интерфейса и бота — по-русски; тексты берём из макетов.
- Type hints там, где не мешают Django.
- Новые зависимости — только с обоснованием в описании задачи.
- Тесты не ходят в сеть: Telegram и прочие внешние API мокаем.
- Новый код покрывается тестами. Обязательно — деньги (сервис, лимиты, комиссия, выплаты, споры) и авторизация.
- В репозитории работают и с Windows: команды и пути в README должны оставаться рабочими.

## Сервер (прод)

- `root@91.108.241.25`, вход по SSH-ключу. Сайт и Mini App: `https://91-108-241-25.sslip.io` (`/app/` — Mini App), TLS даёт Caddy (`deploy/Caddyfile`).
- Код — `/opt/prediction_market/app`, ветка **`miniapp`**, владелец пользователь `pm`; venv — `/opt/prediction_market/venv`; `.env` сервера лежит там же и в git не попадает.
- Сервисы systemd (`deploy/systemd/`): `pm-db` (PostgreSQL в docker compose), `pm-web` (gunicorn), `pm-worker` (`run_worker`), `pm-bot` (`run_telegram_bot`, long polling).
- **Обновить прод** (после пуша в `miniapp`): `ssh root@91.108.241.25 bash /opt/prediction_market/app/deploy/update.sh` — pull, `npm ci` + сборка Mini App, зависимости, миграции, collectstatic, рестарт всех сервисов.
- После изменений в `setup_bot` (кнопка меню, команды бота) — ещё `ssh root@91.108.241.25 "cd /opt/prediction_market/app && sudo -u pm /opt/prediction_market/venv/bin/python manage.py setup_bot"`.
- Логи: `ssh root@91.108.241.25 journalctl -u pm-bot -u pm-worker -u pm-web -n 100 --no-pager`.
- Git на сервере запускать от `pm` (`sudo -u pm git ...`), иначе «dubious ownership».
- На сервере нужен ffmpeg (анимация графика в боте) — ставится `apt-get install -y ffmpeg`, `setup-server.sh` его не ставит.
- **Бот один на токен.** Прод-бот уже опрашивает Telegram — локальный `run_telegram_bot` с тем же токеном даст «Conflict» и будет делить апдейты. Для локальной разработки — отдельный тестовый бот.
- **Не запускай `setup_bot` локально с прод-токеном**: он перепишет кнопку меню бота на локальный `SITE_URL` (ngrok) у всех пользователей.
- Пушить и обновлять прод — только по явной просьбе пользователя.
